## Google DeepMind: Build with Gemini 4 Argon

**Autonomous Agents & Multimodal Applications**
**Prize pool: $15,000 in Gemini API / Google Cloud credits**

| Place | Prize                        |
| ----- | ---------------------------- |
| 1st   | $7,000 in Gemini API credits |
| 2nd   | $5,000 in Gemini API credits |
| 3rd   | $3,000 in Gemini API credits |

Build a working application or autonomous agent powered by Gemini 4 Argon (`gemini-4-argon`), Google DeepMind's new frontier model for software engineering, complex knowledge work, cybersecurity defense and multimodal creation, that solves a specific problem for a real person you can name.

Gemini 4 Argon unifies input, reasoning and output in a single 1M-token context window. It works longer on its own, retains context across large codebases and dense document sets, and pairs as a lead orchestrator with Antigravity Managed Agents and fast companion models for parallel subagents, real-time voice and vision, image, video and music generation, and on-device open models.

### Your challenge

Build and demo a working project that could only be built with Gemini 4 Argon and Google DeepMind's latest model toolkit. You can build in any domain, including Encode London's themes:

**Pathway 1: Autonomous Agents That Ship** (software engineering, cybersecurity and complex workflows)
Build an agent that plans, uses tools, verifies its own output against a concrete pass/fail signal (test suites, compiler output, runtime logs or headless browser checks), and finishes multi-step work end to end. Use `gemini-4-argon` (`thinking_level` "medium" or "high", long decode with `background=True`) or run inside a Google-hosted Linux sandbox with `antigravity-preview-09-2026`.

Ideas:

- A self-healing security and dependency migration agent that reproduces a vulnerability in an Antigravity sandbox, patches it and outputs a visual diff walkthrough
- A legacy codebase modernizer that rebuilds a tested modern web app from an old app and a screen recording
- A research-to-prototype system where Argon coordinates the Deep Research agent and delegates modules to `gemini-3.8-flash` subagents

**Pathway 2: The Real World, Hard Tech & Multimodal Creation** (voice, video, 3D/WebGPU and physical systems)
Build an application that perceives, simulates or creates across real-world video, live voice, spatial 3D/WebGPU environments, or hardware and scientific data, using `gemini-4-argon` and companion models.

Ideas:

- A playable Three.js/WebGPU world where Argon computes the physics or level geometry, `gemini-3.8-live` powers voice interaction and `lyria-3.5` drives the soundtrack
- A manufacturing or lab root-cause analyst that scrubs inspection footage alongside sensor CSVs and long datasheets
- A hands-free voice and screen navigator in 70+ languages with human confirmation before any form is submitted

### Judging criteria

Judges score live working demos, not slide decks (3-minute live demo plus 2 minutes of Q&A).

| Criterion                           | Weight | What judges look for                                                                                                                                                                                                                                                  |
| ----------------------------------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

Did the team use `gemini-4-argon`, Managed Agents or companion models effectively, with a real verification loop?                                                                                             |
| Problem and usefulness              | 25%    | Does it solve a concrete problem for a specific person you can name? Could it grow into a product or open-source tool used after the hackathon?                                                                                                                       |
| Originality / needed Gemini 4 Argon | 15%    | Is it only possible because of Argon's 1M unified context, long decode, frontier reasoning, agentic video analysis, 3D/WebGPU generation or multi-agent orchestration? Does it keep people in control of actions that affect external systems, money or private data? |
| Clarity of pitch                    | 10%    | Did the team show who the user is and demo the working product clearly in 3 minutes, without slides?                                                                                                                                                                  |

### Projects to avoid (disqualified or low-scoring)

- A basic chat wrapper or simple Q&A bot over a single PDF
- A static page with no autonomous reasoning, verification loop or multimodal workflow
- An unverified medical diagnosis, mental health counselling or financial advice bot without human-in-the-loop safeguards
- Anything built before kickoff. Open-source libraries and starter templates are fine, but your demo must only show code written during the hackathon

```bash
pip install -U "google-genai>=2.3.0"

# TypeScript / JavaScript

```

The recommended endpoint is the Interactions API (`client.interactions.create`), which covers models and managed agents, keeps server-side state and supports long background runs.

### Get started in 15 minutes

1. **Claim your credits:** collect your pre-provisioned account or Gemini API credits from the Google DeepMind team at kickoff.
2. **Give your coding agent the Gemini API skills**, so it writes current `gemini-4-argon` and Interactions API code:
   ```bash
   npx skills add google-gemini/gemini-skills --skill gemini-api-dev
   npx skills add google-gemini/gemini-skills --skill gemini-live-api-dev
   # or, in Antigravity:
   agy plugin install https://github.com/google-gemini/gemini-skills
   ```

   Or prototype directly in Google AI Studio Build or Google Antigravity.
3. **Check the Argon API rules:**
   - Use `thinking_level` ("low", "medium" by default, or "high") instead of the deprecated `thinking_budget`
   - Remove `temperature`, `top_p`, `top_k` and explicit `cached_content` (implicit caching is automatic)
   - Set `background=True` to generate past 65,536 tokens (up to 1M)
4. **Ask the mentors** onsite (Amit Vadi and Geneviève Huskens, at the Google DeepMind booth) whenever you hit a blocker.

## Encode Club: The Real World: AI that understands the world around us

Build software that makes sense of the physical world from photos, audio, maps and open data. Most AI still lives in a chat window. This challenge takes it outside: streets, venues, parks, trails, wildlife, the weather and the air we breathe. Combine vision, audio and language models with maps and public datasets to build something that helps people understand, navigate or look after the world around them.

### What to build

Some ideas to get you started. They're starting points, not tracks:

- **Accessibility guide:** describe a street, station or venue from photos, covering step-free access, entrances, signage, seating and noise, for blind and partially sighted people or wheelchair users.
- **"What's happening near me" explorer:** pull live open data (transport, events, roadworks, planning applications, weather) into one view of a neighbourhood, and let people ask questions about it in plain English.
- **Trip or hike conditions planner:** combine forecasts, daylight, terrain, trail reports and transport times to tell someone whether, when and how to go.
- **Wildlife and plant ID:** identify species from photos or sound recordings (bird song, for example) and log sightings on a shared map.
- **City noise or air-quality map:** turn public sensor datasets into a street-level map, a daily briefing or a "quietest, cleanest route" planner.
- **Report it from a photo:** spot potholes, fly-tipping or broken streetlights in a picture and draft the report to the right council team, with the location filled in.
- **Sound-aware assistant:** alert deaf and hard-of-hearing people to sirens, alarms, doorbells or announcements.
- **Label and menu reader:** read a menu, shelf or food label from a photo and flag allergens and dietary needs.
- **Flood and heat risk checker:** explain what an address or route is exposed to, using environmental open data.

### Useful data sources

- **Maps and places:** OpenStreetMap London data, the TfL Unified API and the London Datastore
- **Weather:** the Met Office and Open-Meteo
- **Air quality:** Breathe London and the London Air Quality Network
- **Flood data:** the Environment Agency's flood-monitoring API
- **Wildlife records:** iNaturalist and GBIF

You're free to use any other public data, your own photos and recordings, or hardware such as phone sensors and cameras.

### Judging criteria

- **Real-world usefulness:** a clear user and a problem that exists outside the hackathon
- **How well it reads the world:** accuracy, and sensible handling of messy inputs such as blurry photos, background noise or gaps in the data
- **Technical execution:** a working end-to-end demo that combines AI models with real data
- **Responsibility:** respect for privacy (faces, number plates, people's locations), and honesty about uncertainty when the model isn't sure

### Submission requirements

- A working demo (web, mobile or hardware)
- A code repository with a README and setup instructions
- A 2–4-minute demo video showing it working on real inputs: photos, recordings or live data
- A short note on the models and data sources you used

## Encode Club: Agents That Ship

Build an AI agent that does a real job end to end, not just a chatbot. Pick a task someone does today by hand, in a spreadsheet or across ten browser tabs, and build an agent that sees it through: it gathers what it needs, uses real tools, makes decisions, recovers when something goes wrong and delivers a finished result. A person should stay in control where it matters, approving the risky steps rather than doing the work.

### What to build

Any domain is welcome. Some ideas to get you started:

- **Small-business operations:** chase unpaid invoices, reconcile payments, reorder stock or book suppliers
- **Recruiting:** screen applications against a brief, shortlist candidates and schedule interviews
- **Research:** produce a sourced brief, competitor report or due-diligence pack, checking its own claims before it hands anything over
- **Event running:** find a venue, set up the event page, manage sign-ups and send reminders and follow-ups
- **Developer:** take an issue, write the fix, run the tests and open a pull request ready for review
- **Personal admin:** renewals, refunds, complaints, forms and appointments
- **Agents that work together:** agents that hand tasks to each other, or pay and get paid for work, for example with stablecoins

### Judging criteria

- **Does the job:** it completes a real task from start to finish with minimal hand-holding
- **Reliability:** it handles errors and edge cases, and knows when to stop and ask a human
- **Usefulness:** someone would actually use it, or pay for it
- **Technical depth:** good use of tools, memory, planning and evaluation
- **Safety and control:** sensible permissions, approval steps for risky actions and a clear record of what the agent did

### Submission requirements

- A working demo of the agent completing its task from start to finish, live or recorded
- A code repository with a README and setup instructions
- A 2–4-minute demo video
- A short description of the agent's tools, the steps it takes and where a human approves
